# VSD - Visual Statistics Display

A Flutter desktop app for viewing and analyzing statmonitor data generated by GemStone/S 64 Bit, GemStone/S, or GBS. Use it to monitor performance and diagnose problems in complex GemStone systems. This is the Flutter-based successor to the Tcl/Tk [VSD 5.x](https://gemtalksystems.com/products/vsd/).

## Features

**File loading**
- Open `.out` and `.out.gz` files

**Process & statistics exploration**
- Browse loaded processes with start/end times and sample counts
- Drill into per-process statistics and view stat metadata: description, units, and min/max/avg values

**Charts**
- Plot any statistic as a line chart with a trackball tooltip for precise point inspection
- Compare multiple statistics side by side

**AI assistant**
- Ask natural-language questions about the loaded data
- Requires your own Anthropic API key

## Getting Started

```sh
flutter pub get
flutter run -d macos   # or -d windows / -d linux
```

## Releasing (macOS)

`tool/release_macos.sh` builds, signs, notarizes, staples and packages the app,
producing `build/macos/dist/vsd-<version>.dmg`.

It needs the **Developer ID Application: GemTalk Systems LLC (72G58AHU7P)**
certificate in the login keychain, plus notarization credentials stored once:

```sh
xcrun notarytool store-credentials vsd-notary \
  --apple-id you@gemtalksystems.com \
  --team-id 72G58AHU7P \
  --password <app-specific-password>
```

App-specific passwords come from [appleid.apple.com](https://appleid.apple.com)
→ Sign-In and Security → App-Specific Passwords. Then:

```sh
tool/release_macos.sh                  # signed + notarized DMG
tool/release_macos.sh --skip-notarize  # signed only, for local testing
```

In CI, set `APPLE_ID` and `APPLE_APP_PASSWORD` instead of storing a profile.
Note this requires a macOS runner — the GitLab pipeline currently uses a Linux
Flutter image and does not build the macOS app.

The release build uses the hardened runtime and the App Sandbox
(`macos/Runner/Release.entitlements`). The sandbox grants network access and
**read-only** access to user-selected files; adding any write capability means
adding the matching entitlement there.
